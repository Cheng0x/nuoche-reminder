# 车辆挪车提醒 — 设计方案

> 项目代号：`nuoche-reminder`
> 一句话目标：一辆车挡了路，路人扫码/打开页面，一眼看到「挡路抱歉」，一键把话术送到车主飞书并电话加急，还能借 12123 一键挪车、顺便种草同款车。

## 1. 项目概述

这是一个**移动端网页**（H5），服务两类人：

- **被挡路人**：需要快速、礼貌地联系挡路车主；
- **车主**：把页面二维码贴在车上，降低被砸车/被投诉的概率，同时借机「买同款」引流。

核心体验路径（黄金路径）：

```
扫码/打开页面 → 看到「挡路抱歉」+ 车辆信息卡(含绿牌)
  → 选择或输入一句挪车话术
  → 点击「发送挪车提醒」
  → 后端把话术发到车主飞书，并设置电话加急
```

## 2. 需求拆解

| # | 需求 | 落地方式 |
|---|------|----------|
| 1 | 移动端网页 | 移动优先（375px 基准）的响应式单页，无刷新交互 |
| 2 | 车辆品牌/颜色/车牌 | 信息卡：小米 SU7 Pro、赤霞红、鲁CDN0940；车牌按新能源绿牌样式渲染 |
| 3 | 一眼看到挡路抱歉 | 首屏大字号「挡路抱歉」+ 副文案，视觉最高优先级 |
| 4 | 话术选择 | 4 条常驻话术 chips + 自定义输入框 |
| 5 | 发送到飞书 + 电话加急 | 后端飞书集成：机器人 Webhook 发消息 + Open API `urgent_app` 电话加急 |
| 6 | 12123 一键挪车 | 按钮触发**从下到上**的底部弹窗（Bottom Sheet），内附操作步骤 |
| 7 | 买同款 | 按钮触发弹窗，展示小米汽车内推图片 |

## 3. 技术选型

| 层 | 选择 | 理由 |
|----|------|------|
| 前端 | 原生 HTML + CSS + JavaScript（无构建） | 单页、交互轻、零依赖、易部署、易改 |
| 后端 | Node.js + Express | 飞书 Webhook/Open API 需要服务端保存密钥，不能暴露在前端 |
| 配置 | `dotenv` + `.env` | 飞书凭据按环境注入，不进代码库 |
| 托管 | 静态文件由 Express 托管，同源接口 `/api/*` | 免跨域、一键 `npm start` 起服务 |

> 说明：发送到飞书**必须走后端**——飞书自定义机器人 Webhook 的签名密钥（secret）与应用的 App Secret 若写进前端 JS，等于公开泄露。因此把「发消息 + 电话加急」收敛到 `/api/send` 一个接口。

## 5. 飞书「电话加急」集成方案

飞书自定义机器人 Webhook **只能发消息、不能加急**。电话加急必须走开放平台 API。流程：

1. 用 `app_id` + `app_secret` 换 `tenant_access_token`（`/open-apis/auth/v3/tenant_access_token/internal`）。
2. 用 `receive_id`（车主 open_id / user_id / 手机号）通过 `im/v1/messages` 给车主发私聊消息，拿到 `message_id`。
3. 调 `im/v1/messages/:message_id/urgent_phone`（**电话加急**，`PATCH`，请求体 `{ user_id_list: [...] }`），对该用户触发电话提醒；短信/应用内加急分别对应 `urgent_sms` / `urgent_app` 端点。

降级策略（保证无凭据时也能演示）：

- 只配 `FEISHU_WEBHOOK_URL`：发群消息，返回 `sentVia: webhook`（无加急）。
- 配了 App 凭据 + `FEISHU_RECEIVE_ID`：发私聊 + 电话加急，返回 `sentVia: app, urgent: phone`。
- 都未配：接口返回清晰的 `503` 提示 + 前端 toast「尚未配置飞书，请参照 README 配置」，避免静默失败。

### 环境变量（`.env`）

```dotenv
PORT=3000
# 方式一：自定义机器人（发到群）
FEISHU_WEBHOOK_URL=
FEISHU_WEBHOOK_SECRET=
# 方式二：企业自建应用（私聊 + 电话加急）
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_RECEIVE_ID=        # 车主 open_id / user_id / 手机号
FEISHU_RECEIVE_ID_TYPE=open_id   # open_id | user_id | chat_id
FEISHU_URGENT=phone       # phone=电话加急 | sms=短信加急 | none=不加急
```

## 8. 关键设计决策

1. **车牌用纯 CSS/SVG 渲染**而非图片：可缩放、清晰、好维护，同时能精确还原绿牌渐变与圆点分隔。
2. **自定义输入优先级高于 chips**：输入非空即发送自定义文案；清空则回落到选中 chip。避免两套状态打架。
3. **底部弹窗用 transform 过渡**：12123 弹窗从下到上（`translateY(100%) → 0`），符合移动端手势习惯，硬件加速流畅。
4. **发送态要有反馈**：按钮 loading + 成功/失败 toast，且失败信息可读（区分「未配置」「网络失败」「飞书报错」）。

## 9. 安全与约束

- 飞书密钥只存服务端 `.env`，`.gitignore` 排除；仓库只放 `.env.example`。
- 后端对 `text` 做非空校验、长度上限（如 200 字）、去首尾空白。
- 前端无任何第三方 CDN 依赖，离线/内网可运行。
- 12123 说明为公开功能指引，不涉及账号代操作，规避合规风险。
